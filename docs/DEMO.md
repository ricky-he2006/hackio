# Three-minute Disco demo

Rehearse with the local deterministic mode first. Connect a real provider and rehearse again before recording. Keep provider mode visible so the audience can distinguish local checks from model-backed agents.

## Preparation

1. Start the server and open `/demo` in a browser at laptop width.
2. Use the toolbar to log into all four prepared accounts.
3. Dismiss each introductory memory card. Keep all four views signed in.
4. Make sure the selected day is Saturday or Sunday, as seeded availability covers those days.
5. Keep a recording as a backup for network/model failures.

## Suggested story

**0:00–0:20 — The problem.** “Your friends know the best spots. Getting everyone there is the hard part.” Introduce Disco’s two connected capabilities: friend-backed recommendations and private group planning.

**0:20–0:50 — Recommendations.** On Ricky’s phone, ask: “Find restaurants my friends love.” Open a card to show the actual stored quote and its author. Note that the seed opinions are fictional demo data. If web search is configured, show one source for current venue details.

**0:50–1:25 — Agents coordinate.** Choose “Round up my crew,” select Aditya, Arnav, and Daniel, and start with Saturday at 7 pm and a $24 proposed meal allowance. The seeded constraints lead the local flow toward 8:30 pm and a lower allowance. Show the private negotiation lanes. The host never sees anyone’s exact personal budget or reason.

**1:25–1:50 — Approval and live invitations.** Ricky approves. Invitations appear on all three other phones. Accept as Aditya and Daniel; then accept as Arnav. The plan becomes confirmed.

**1:50–2:25 — The second act.** In Arnav’s chat, say: “Can’t do 8:30, could do 9.” The agents reopen negotiation. Show the host’s before/after time. Ricky approves the update; the others get a reconfirmation. Memory asks for explicit consent; choose “Just this time” for this example.

**2:25–2:45 — Learning.** If time permits, add a positive opinion as Daniel and show Ricky’s rankings update. Open Daniel’s friend profile to show public Been and Want to try lists, then open the notification inbox. Explain that each outing makes the next recommendation better. Skip this live step if the video is running long.

**2:45–3:00 — Impact and next step.** Show simulated booking confirmation or calendar download. “Next, the same approved plan can connect to restaurant reservations. People make the social decisions; their agents handle the coordination.” Mention one actual technical challenge: enforcing privacy while still making the negotiation visible.

## Useful chat phrases

- `Find restaurants my friends love`
- `Plan Saturday with Aditya, Arnav, and Daniel`
- `Keep tonight under $15`
- `Can’t do 8:30, could do 9`
- `I prefer quiet restaurants`
- `What do you remember about me?`
- `I loved North Market Downtown, 9.5/10. Great variety for a group.`

Use the review form when an item’s name is ambiguous. Local-mode interpretation is intentionally limited; configure a model for broader language understanding.

## Honest demo labels

- The people/opinions in the seed network are demonstration fixtures.
- A meal allowance is a proposed budget for the outing, not a live menu price.
- Local agents are deterministic, not LLMs.
- Web results require a working search provider and source verification.
- Booking is simulated. Calendar download is real; calendar-account sync is deferred.
- Friend profiles and notifications are viewer-scoped public projections; private constraints and raw chat never appear there.
- Invite links resolve to prepared Disco accounts in the demo; non-user invitations remain deferred.
- “Near me” uses browser location only when allowed and otherwise clearly labels the seeded OSU fallback.
