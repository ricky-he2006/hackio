The questions that shaped Disco
RAAD
Can a group find a plan if nobody shares their limits?
We testedTreated each friend’s agent as a private yes/no oracle.
We builtA coordinator that searches times, $5 steps and venues from ✓/✗ answers alone.
Even with no field leaked, can someone infer a friend’s budget?
We testedAttacked our own app: proposed allowances to one friend and watched the answers.
We builtHidden verdicts, $5 steps, 12 negotiations per friend per day.
What can only a model judge?
We testedBuilt an agent eval set and compared model vs. code decisions.
We builtBudget, schedule and diet rules in code; the model judges soft fit only.
Can a hostile venue name or web page hijack an agent?
We testedPrompt-injection tests with hostile names and model output.
We builtOutput parsed as data; only offered IDs accepted; uncited claims never “verified”.
How do we trust a “halal” or “vegetarian” claim?
We testedCompared web claims against friends’ tagged reviews.
We builtStrict diets need evidence, plus a private “check with the restaurant” note.
Could Disco notice a plan before anyone asks?
We testedExplored triggers: shared saves, similar interests, events.
We builtOpt-in suggestions when friends save the same spot; nobody named until all agree.
THE CLEVER PART

The coordinator never reads a budget.

It finds the plan by asking each private agent “does this work for you?”, then tries the next option. The host only ever sees “a cheaper option is needed”, never whose limit or why.
